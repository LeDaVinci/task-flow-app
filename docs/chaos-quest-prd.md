# Chaos Quest PRD

状态：讨论稿 v0.1  
更新时间：2026-09-01

## 1. 产品定位

Chaos Quest 是一个面向下班后生活的行动启动器。它不要求用户变得自律，而是在低能量、生活事务散乱或情绪低落时，帮助用户找到一个轻量、具体、能立刻完成的下一步，让用户重新获得一点生活掌控感。

## 2. 要解决的问题

下班后，用户往往同时面对疲惫、无聊、生活杂务和情绪波动：

- 想让生活变好一点，但不知道从哪件事开始。
- 知道有许多事情要做，却因任务模糊或能量不足而拖延。
- 最终被动刷手机、躺平，之后对自己产生挫败感。

## 3. 目标用户与核心场景

目标用户：下班后有一定自主时间，但精力有限、生活事务分散、需要轻推一把的人。

核心场景：

1. 低能量或情绪低落，需要一个不费力的恢复行动。
2. 生活杂务堆积，希望推进一件具体的小事。
3. 想梳理今晚、这周与以后再说的事情，降低脑内混乱。
4. 下班后感到无聊或空虚，希望做一点能留下记忆点的事。

## 4. 产品目标

1. 降低从“我想做点什么”到“我开始做”的阻力。
2. 让用户在当晚完成至少一件对自己生活有益的事。
3. 让完成、休息和调整都成为正反馈，而非自我苛责。
4. 通过长期偏好学习，使推荐越来越贴合用户的现实处境。

## 5. 核心体验闭环

首页操作区 → 选择任务类型 → 生成 1 个任务 → 执行或重掷 → 一键完成 → 获得 XP → 离开应用

## 6. MVP 功能范围

### 6.1 首页操作区

首版保持当前首页的轻量卡片式交互，不新增多步问答、独立任务选择页或输入表单。

- 抽轻支线：获得轻量、低压力的生活行动。
- 抽混沌支线：获得更有新鲜感或突破感的生活行动。
- AI 生成：先输入想要的任务主题，再通过 API 动态生成一项任务。
- 召唤 Boss：主动选择更有挑战的任务。

统计信息与进行中的支线列表继续保留，让用户能快速看到当前任务和已积累 XP。

### 6.2 任务生成

- 任何时刻只保留 1 个进行中的任务；任务生成后直接展示在进行中的支线区域。
- 存在进行中任务时，不再新增或排队其他任务。用户需完成、归档或重掷当前任务后，才能生成下一项。
- 重掷只替换当前任务，不额外创建任务。
- 任务生成后提供“再来一个”；点击后按当前任务类型重新生成，并直接替换当前任务。
- 模板生成用于抽轻支线、抽混沌支线与 Boss；AI 生成通过 API 动态生成任务。
- 点击 AI 生成后，使用轻量弹窗或底部输入层收集一句主题描述，不跳转到新页面。
- 用户可输入主题，例如“收拾衣柜”“整理一下厨房”“让我缓一缓”；该输入是 API 生成任务的边界。
- 用户也可不输入主题，直接点击“随机来一个”；系统使用随机任务范围生成。
- 用户点击 AI 生成后，按钮进入加载态并暂时不可重复点击；首页显示俏皮的轮播加载提示：
  - “正在翻找今晚的隐藏支线…”
  - “正在给生活事务套上任务皮肤…”
  - “正在避开无聊选项…”
  - “正在挑一件你现在就能做的事…”
- 生成成功后，显示“AI 已生成新支线”并将任务置顶。
- API 不可用或生成失败时，自动回退模板任务，并提示“AI 暂时不可用，已换成随机支线”。

随机任务不等于无边界，须满足：

- 服务下班后的真实生活，而非工作任务。
- 优先在 15 到 30 分钟内完成。
- 低风险、低成本、无需专业工具或外部承诺。
- 完成后带来可感知的正反馈：环境更舒适、生活事务更清晰、身体或情绪更放松，或产生一点新鲜感。
- 候选方向包括生活整理、个人照料、轻量规划、轻社交、恢复行动与微型探索。

### 6.3 执行与完成

- 任务卡展示行动内容、预计时长、完成信号与可获得 XP。
- 用户按自身节奏在现实中执行；首版不增加强制计时或专注页。
- 用户可重掷当前任务，或归档不想继续的任务；不产生惩罚。
- 用户点击“完成”即可结束任务，系统立即发放 XP，并用简短反馈确认本次完成。
- 用户完成后可直接离开应用；首版不要求文字、照片或结果记录。
- 未完成任务在次日自动注销：不计完成、不自动延续、不产生惩罚。

### 6.4 XP

XP 是完成行动后的轻量正反馈，不是效率排名。

- 完成任务获得 XP。
- 首版任务时长限定为 15 或 30 分钟，分别获得 15 或 30 XP。
- 首版展示并累计总 XP，不提供兑换或奖励池配置。
- 换任务、退出、未完成均不扣 XP。

奖励池是后续方向：用户可为饮品、娱乐时间、鲜花、休息或小物件设置 XP 兑换目标。

## 7. 非目标

- 不做复杂的工作待办、项目管理或排期工具。
- 不以连续打卡、排名、惩罚驱动用户。
- 不强制社交或公开分享。

## 8. 成功指标

- 任务生成后的启动率。
- 已启动任务的完成率。
- 用户选择“换一个”的比例。
- 完成后次日回访率。
- 用户对任务“适合当下”的主观评价。

## 9. 待确认决策

1. 任务完成后，首页是否保留最近完成任务，还是只保留累计 XP？
2. 奖励池后续以用户自定义为主，还是同时提供系统推荐？

## 10. 首版实现计划

### 10.1 当前版本与目标差距

| 模块 | 当前版本 | 首版目标 |
| --- | --- | --- |
| 任务数量 | 预置 3 个任务，且可持续新增多个进行中任务 | 首次打开为空；任何时刻只有 1 个进行中任务 |
| 任务生命周期 | 仅内存保存，应用重启后重置 | 保存当前任务和 XP；跨日自动注销未完成任务 |
| 重新生成 | 归档旧任务后新增任务 | 仅替换当前任务，不产生队列或历史压力 |
| AI 生成 | 已有 API 调用和模板回退，但无加载状态 | AI 按钮加载、轮播提示、成功提示、失败回退提示 |
| XP | 按难度与时长计算，仅基于本次内存数据统计 | 仅按 15/30 分钟发放 15/30 XP，并持久化累计总值 |
| 首页 | 已具备操作区、统计区、任务卡 | 保持整体视觉与操作区，不做大幅交互重构 |
| 本地模型 | 底层代码和 App Functions 保留，入口已隐藏 | 保持现状，不再作为首版用户功能 |

### 10.2 P0：单任务与每日生命周期

1. 移除初始示例任务，首次打开显示空任务板。
2. 将任务状态收敛为“当前进行中任务 + 累计 XP”；生成前先检查是否已有进行中任务。
3. 有进行中任务时，不允许从首页新增任务；仅可完成、归档或“再来一个”替换当前任务。
4. 将“再来一个”改为原地替换，不保留被替换任务。
5. 增加本地持久化，保存当前任务、创建日期与累计 XP。
6. 应用启动和回到前台时检查日期；当天未完成任务跨日后自动注销。

### 10.3 P0：AI 生成体验

1. 为 ViewModel 增加 AI 生成中的状态。
2. AI 按钮点击后显示轻量主题输入层；用户可输入主题或选择随机生成。
3. AI 按钮生成期间显示加载态并禁止重复点击。
4. 按固定间隔轮播 4 条加载文案。
5. API 成功后显示“AI 已生成新支线”；失败时回退模板并显示既定提示。
6. 更新 API 提示词与模板规则，确保随机任务符合下班后生活、15～30 分钟、低风险低成本的范围。

### 10.4 P0：XP 与任务展示

1. 任务时长收敛为 15 或 30 分钟，XP 与时长一一对应。
2. 完成任务时只做一键完成、累计 XP、简短成功反馈。
3. 不增加计时页、完成留痕、奖励池或任务队列。
4. 保持现有首页卡片布局，仅将任务展示改为单任务状态。

### 10.5 P1：验证与收尾

1. 覆盖单任务限制、重掷替换、跨日注销、XP 累计、API 失败回退的测试。
2. 验证 Release R8 压缩与签名构建。
3. 根据“已通关任务是否展示”的产品决策，保留或移除首页完成历史区。
